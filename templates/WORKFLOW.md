# eli｜协作引擎：可执行工作合同

## 参与者

- **用户**：提出目标、确认重大业务取舍、额外付费与高风险操作。
- **主控 eli（普通 ChatGPT）**：拆解目标、读取工具能力、派单、接收结果、重要技术判断、复测、Git 提交和项目检查点。
- **Codex 执行器**：在明确的权限、工作目录、范围和超时内完成代码任务，可在同一有效原生会话内被主控追问。

## 最小状态机

`NEW` → `TOOLS_VERIFIED` → `DISPATCHED` → `AWAIT_RESULT` → （`NEEDS_CONTROLLER` ↔ `DISPATCHED`）→ `INDEPENDENT_REVIEW` → `ACCEPTED` / `BLOCKED`。

任何时刻发现 `UNKNOWN_SIDE_EFFECT` 或 `PERMISSION_REQUIRED`：先停下并保存可复核状态；除非有明确批准或安全可逆方案，否则不能“自动重试”。

## 主控每次派单必须给的信息

- 目标与完成标准。
- 仓库/临时工作区（不能用模糊的全盘权限）。
- 文件与工具访问范围、是否只读、是否允许写入。
- 模型/推理档位要与真实 catalog 一致。
- 时间限制与最大重试次数；默认重试 0。
- 结果要求：原始任务状态、代码 diff、测试回执、问题与风险。

> 正式 Mac MCP 版本的工具字段可变。示例名为 `spawn_agent`、`wait_agents`、`get_agent`、`agent_action(message)`；先读**实际 tool_discover/schema**，不要把这里当作可直接 POST 的私有 API。

## 回合往返范式

**Luna 反馈**：

```text
NEEDS_CONTROLLER:
原因：当前仓库依赖 A 可能破坏既有文件格式。
备选：A 保留兼容层 / B 直接迁移。
推荐：A，因为可回退且覆盖旧数据。
需要主控决定：是否保留兼容层？
当前改动：尚未写入，0 个文件。
```

**eli 回复**：

```text
DECISION: 选择 A；仅改 parser.py 的读取路径；新增兼容旧格式的回归测试；不改变旧数据。
继续使用相同 provider-native session。返回变更文件、测试命令和真实结果。
```

Codex 如果返回“无法访问旧 session”，主控先保存实际失败与旧 session 的历史指针，再从可验证的 Git HEAD 和任务状态新开**Codex 执行会话**接力；这不等于恢复原云 Work。

## 主控独立验收的条件

1. `get_agent` 显示完成，而且会话身份、权限和副作用可核查。
2. `git status` / diff 与用户批准范围一致。
3. 能实际跑的测试确实在**源仓库**重跑；隔离工作树无法访问 gitdir 的情况由主控在有权限的真实源目录补验。
4. 需要合并隔离改动时，通过官方有 CAS 或等价检查的 apply 流程，不能直接粗暴覆盖原文件。
5. Git 提交与本地进度记录真实存在且可重新读取。源目录被其他进程改动时停止盲目合并。

## 成本与停止门槛

- 优先保留高质量主控判断；高频执行选择当前账户实际可用的合适模型。作者实例选择 GPT-6 Luna XHigh，不承诺所有账号都有。
- 当准备调用更高成本/高消耗模型时，先看**自己账号当前**额度和重置窗口。额外付费由用户或账户政策确认。
- Chat 与 Work/Codex 分额度，Work 与 Codex 共享工作额度，具体用量并非固定任务次数。不要宣传无限免费。
- 除非用户明确配置专门的后台任务、账户与运行权限，**结束对话就不宣称仍有人自动调度**。
