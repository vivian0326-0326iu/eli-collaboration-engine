# 必须真实执行的连接与验收（不能凭提示词判 PASS）

## A-D：普通 Chat → Mac MCP → Mac

建立一个**单独演练目录**，绝不直接拿下载文件夹/桌面全部文件做测试。由有工具权限的普通 ChatGPT 使用当前可用的 Mac MCP 官方工具做：

| 关卡 | 实际操作 | PASS 证据 |
|---|---|---|
| A | 普通 Chat 真实调用 Mac MCP 只读状态/发现工具 | 工具自身返回有效版本、连接状态，而非 AI 自称连上了 |
| B | 在指定安全目录调用 list_directory/read_file | 返回文件路径、内容（非敏感）与成功状态 |
| C | `write_file` 新建 `eli-smoke.txt` 并 `read_file` | 标记内容逐字相同，真实文件事务回执 |
| D | `edit_file` 修改一行，再 `read_file` | 预期替换一次，二次回读内容逐字一致 |

若标准权限不允许写入，C/D 是 **BLOCKED_PERMISSION**；不应把只读 A/B 写成 A-D 全 PASS，更不能擅自放大到 `trusted`。用 `/health` 200 取代 MCP 工具调用也是错的。

## E-G：真实 Codex 原生双向协作

**E**：Mac MCP `agent_catalog` 列出真实 Codex provider，发现所选模型及 reasoning；只读 `spawn_agent` 用一个不会触及秘密的短任务，比如“读取演练文件并返回标记行”。记录 `agent_id`、`provider`、`model`、`access_mode`、`native session`、`workflow_id`。`spawn_agent` 返回 running ≠ 完成。

**F**：有界 `wait_agents` 后使用 `get_agent(result_mode="full")` 核查 `completed`、真实 summary、工具调用数量、完整输出、有无 truncated/omitted；如 `wait_agents` 自身超时，不能误报代理失败。

**G**：通过 `agent_action(action="message", agent_id=...)` 向**同一个 Codex provider-native 会话**发一次无工具的补充提问，例如让它引用上一轮的标记。再核对新 agent 的 parent / native session 和真实答案。只有 `session_id` 与前一轮一致且确实用到历史信息，才写 `SAME_SESSION=PASS`。若 `no rollout found`，标 FAIL，停止重复碰运气。

## H：带隔离代码修改与独立验收

1. **先验证错误存在**。在 `examples/bug-demo` 演练目录运行测试，故意的负数相加测试应失败。把 demo 复制到你创建的新 Git 仓库，不要直接改用户工作项目。
2. 通过 Mac MCP 调用 `spawn_agent`，范围限定为演练 Git 仓库，选择可用的 Codex 模型，`access_mode=workspace_write`、`git_isolation=required`（工具支持时，无法保证则停止写入）、有界超时、`retries=0`。
3. 从 `get_agent` 取回变更范围和 `worktree` 元数据，不能因为代理说“通过”就放行。
4. **主控独立**检查 Git diff / `git diff --check`；必要时 `agent_action(action="apply")` 将隔离补丁合并进用户演练仓库，发生源文件冲突时不自动 `git reset --hard`。
5. 运行 `python3 -m unittest discover -s . -p 'test_*.py' -v` 确认两项 demo 测试通过；提交 Git 后记录 SHA。
6. 做一次普通技术反馈，把明确的改进建议送回执行器原 session；若 session 已不可恢复，记录失败后从可信 Git 接力，而非新开 ChatGPT 云 Work。

**H 通过的最低证据**：真实 agent_id 与 session、原生代理结果、隔离变更、源仓库测试通过、Git SHA、主控独立验收日志。
