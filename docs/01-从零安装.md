# 从一台没有配置的 Mac 搭建

## 0. 先确认：是不是可实现的账号和设备组合？

这里描述的版本是 **Mac + ChatGPT 普通聊天中的 MCP 工具 + Codex CLI + Mac MCP**。项目不替代上游工具，也不需要克隆作者私人电脑的全部配置。只有真实建立连接，普通 Chat 才能直接与 Codex 双向往返。

| 前提 | 怎么判断 | 缺失时怎么办 |
|---|---|---|
| Mac (macOS) | Apple 菜单 → 关于本机 | Windows/Linux 别套用 Mac MCP 的系统权限步骤；换平台须重新设计 |
| Python ≥ 3.10 | `python3 --version` | 安装官方 Python 或 Mac 上已有的 3.10+ 版本，不覆盖系统 Python |
| Git | `git --version` | 按 macOS 官方提示安装 Command Line Tools 等 |
| 当前 ChatGPT 账号允许完整自定义 MCP 连接及写入 | 在 **当前** Web 普通聊天 Plugins 里确认能添加并调用自定义服务 | **阻断项**：本仓库不能给你的账号“变出”权限；需符合账号/工作区要求 |
| Codex CLI 和可用模型 | `codex --version`，Codex 登录后查询可用模型 | 登录自己的账号；模型等级以当前 catalog 为准 |
| 本机 Mac MCP 已安装和授权 | Mac MCP 菜单栏 Settings、`mac-mcp status` | 按官方发布包安装，按需授予 macOS 系统权限 |

**关键现实约束**：截至本项目资料整理，OpenAI 官方对完整自定义 MCP（特别是写入）的公开适用范围、审批流程和入口限制按 Business/Enterprise/Edu 工作区说明；个别个人账户界面可能存在不同能力，但**不能由作者实测代替你自己的账号资格**。官方：https://help.openai.com/en/articles/12584461-connecting-custom-mcp-servers-in-chatgpt 。如果连入口都没有，这条“普通 Chat 直接写文件/派代理”的路径不能复刻成功，先停止而不是埋头改提示词。

## 1. 下载本开源仓库

在 GitHub 项目首页点绿色 **Code → Download ZIP**，解压后打开 `README.md`，或者在终端执行 `git clone <你的真实仓库URL>`。当前交付没有上传到某个固定 GitHub URL，**不要复制伪链接**。

如果已经有一个自己的 Git 仓库，先在其副本演练，再运行：

```bash
# 在这个开源包根目录运行；最后一个参数换成你的真实Git项目目录
sh scripts/install_local.sh "$HOME/path/to/your-git-repository"
```

此脚本只把模板、Skill 和本地记录代码复制到目标 Git 仓库；**不会**安装第三方工具、登录账号、开启公网服务、改安全档位或调用模型。遇到现有 AGENTS.md 等文件会拒绝覆盖。

然后确认目标 `.gitignore` 包含 `.eli-engine/`，提交这些模板文件。之后再在目标 Git 仓库里初始化状态：

```bash
python3 scripts/checkpoint.py init --name '我的项目'
python3 scripts/checkpoint.py note --done '建立本地仓库模板' --next '完成Mac MCP连接和四关验收'
python3 scripts/checkpoint.py snapshot --reason '初始已审查Git基线'
python3 scripts/checkpoint.py verify
```

## 2. Codex CLI（官方）

项目默认使用与自己账户授权匹配的 Codex。按官方说明安装；有 Node/npm 之后可选择：

```bash
npm install -g @openai/codex@latest
codex --version
codex login status
```

若尚未登录，在**用户自己的本地终端**运行 `codex` 或 `codex login` 并按官方浏览器步骤登录。不要把登录 token、Keychain、`~/.codex/auth.json` 发给任何人。官方：https://developers.openai.com/cookbook/examples/codex/using_goals_in_codex

**模型差异**：作者实际工作时使用的 `gpt-6-luna/xhigh` 不是对其他账号的授权保证。Mac MCP `agent_catalog` 查询当前实际可用的模型与 reasoning 值。若不可用，请先由用户确定接受的替代，不要假装“低模型一定一样聪明”。

## 3. Mac MCP（第三方独立项目）

上游地址：https://github.com/bulutarkan/mac-mcp

首选官方 GitHub Releases 下载安装包：Apple Silicon/macOS 14+ 支持 `.pkg`；其他 Mac 以发布说明为准。**不要从小红书私聊、网盘、陌生站点下载所谓配置包，也不要盲跑来历不明的 `curl | bash`。** 安装前自行验证发布来源与官方提供的哈希/签名信息。

按照 Mac MCP 首次启动引导，仅授予任务必需的 macOS 系统权限。先采用较小权限，不因为写入能力暂不可用就暗中升级全局 `trusted`；需要写入时先理解 Server Approval、权限范围和风险，由用户本人选择。安装后执行：

```bash
# 某些安装路径为 ~/.local/bin/mac-mcp
mac-mcp status
```

如果 `mac-mcp` 不在 PATH，可尝试 `"$HOME/.local/bin/mac-mcp" status`；**status 显示服务运行不等于 ChatGPT 已连接。**

上游官方文档：
- [主 README](https://github.com/bulutarkan/mac-mcp)
- [代理、Git 隔离工作树、持久会话与定时任务](https://github.com/bulutarkan/mac-mcp/blob/main/docs/agents-and-tasks.md)

## 4. 连接自己的 ChatGPT

普通 ChatGPT 不能直接读取你本机 `127.0.0.1` 的 MCP 端口，需要由账户允许的远程 MCP 通道接入。优先使用官方支持的 **Secure MCP Tunnel**；如果选择用户自行维护的公网 HTTPS 隧道，必须保留 MCP 认证、HostGuard 和 TLS，不要未经同意开放公网。

根据官方目前的 Plugins 界面：

1. 在适用账号的 ChatGPT Web 里打开 Plugins；
2. 点添加，选 **Add custom MCP server**；
3. 填服务名（例如 `My Mac MCP`）和**自己拥有的** HTTPS MCP URL 或官方 Tunnel；
4. 在官方界面完成认证、查看风险提示并确认；
5. 创建插件，查看可用工具；
6. 在普通聊天中实际调用一次只读工具。

具体 UI 随版本与工作区政策变化。**不要把 URL 后面带 `ApiKey` 查询串的完整链接发给 ChatGPT 文本或放进截图。** 官方帮助：https://help.openai.com/en/articles/12584461-connecting-custom-mcp-servers-in-chatgpt

如果此处被套餐、工作区、地域或管理员权限拦住：记录 `BLOCKED_ACCOUNT_PERMISSION`。Mac MCP 本机安装成功也不能跨过 ChatGPT 的账号能力限制。不能通过一个 SKILL.md 解锁权限。
