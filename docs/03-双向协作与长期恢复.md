# 双向协作、请示、回滚与本地持久记录

## 三个完全不同的 ID

- `chatgpt_work_thread_id`：ChatGPT 云 Work 聊天 ID；这套项目**不承诺自动向指定旧 Work 发送消息**。
- `native_session_id`：Codex 原生多轮对话 session；成功的 `agent_action(message)` 可继续当前真实 native session。
- `agent_id`：Mac MCP 记录某次代理执行的 ID；新一轮可能产生新 `agent_id` 但 `native_session_id` 不变。

别因为 `get_agent` 读取了旧状态，就认定旧 native session 一定能恢复。先校验真实身份、工具权限、已提交副作用，才能尝试继续。

## 双向协议的实际样例

Codex 遇到实质性取舍，而非普通自己能修的 Bug 时，在结果最前写：

```text
NEEDS_CONTROLLER: 是否保留旧 API 的向后兼容？
已经核实：当前代码 A 会影响测试 T。
可选：方案A继续兼容；方案B移除兼容。
推荐：A。风险：增加两个分支和测试。
本轮副作用：只读，未写任何文件。
```

eli 主控核对回执和证据之后做出决定，再经现有 Mac MCP 官方消息接口发回：

```text
DECISION: 采用A。先补对旧接口的回归测试，再修最小改动。保留现有 API。
不要重复上一轮已发生的写入。完成后给出实际差异和测试结果。
```

第二轮必须验证与前一轮 session ID 一致；否则别称“原生对话继续成功”。

## 本地记录命令（在你自己的 Git 项目里）

在 `.gitignore` 添加 `.eli-engine/`，先提交当前准备文件。脚本不会自行创建代理，仅保存经主控**真实核验后转录的元数据**：

```bash
python3 scripts/checkpoint.py init --name '我的项目'
python3 scripts/checkpoint.py note --done '真实A-D验证通过' --next '准备Codex只读派单'
python3 scripts/checkpoint.py snapshot --reason '首个干净的Git基线'
python3 scripts/checkpoint.py verify

# 填入你自己get_agent真实回执的ID，不要照抄下面的示意值
python3 scripts/checkpoint.py bind --provider codex --agent-id agt_abcd123456 --session-id session_12345678
python3 scripts/checkpoint.py snapshot --reason '核实了真实Codex绑定'
python3 scripts/checkpoint.py plan

# 假设下一轮agent确实发了需要主控决策的报告
python3 scripts/checkpoint.py report --agent-id agt_efgh123456 --session-id session_12345678 --outcome needs_controller --summary '是否保留旧API？'
python3 scripts/checkpoint.py decide --answer '保留并补回归测试'
python3 scripts/checkpoint.py snapshot --reason '主控决定已验收'
python3 scripts/checkpoint.py plan
```

**注意**：`checkpoint.py report` 从不自动读取或验证 Mac MCP 的 signed receipts。`plan` 只输出本地 `VERIFY_AGENT_LIVE_FIRST` 候选，不能绕过工具实际权限。每当本地任务或 Git HEAD 变化，要再 `snapshot`；此前快照会安全地拒绝放行。

## 出错场景（执行器不该骗过主控）

- **连接不可用**：是当前会话没插件还是 Mac MCP 服务掉线？先分别核查；不要循环重新安装服务。
- **代理 timeout**：先读真实状态与副作用；未知副作用不得自动重试。`checkpoint.py report --outcome timeout` 会将项目标记为 blocked。
- **`no rollout found`**：旧 Codex 历史可读但 native session 失效，先冻结；从 Git HEAD、已提交产物和任务摘要建立*新的 Codex 原生*执行器接力，这不是云 Work 续接。
- **隔离Git worktree 看不到 .git**：可能是子代理沙箱权限不能读外部 Git metadata；若模型已修改隔离树，不自动认定完成，主控在正式仓库独立 diff/test 再 apply。
- **Git 或任务有变动**：`checkpoint.py verify/plan` 应失败。主控审查修改后，先 commit 再 snapshot。不能为通过验收硬 reset 用户变更。
- **咨询轮次过多**：脚本提供有限咨询/恢复状态，但并不限制正在运行的 provider 的 token 或账单，真实余额以账号官方显示为准。
- **Mac MCP 被授予 trusted**：不等于每个写入都受系统强制审批；谨慎启用单独 Server Approval 及最小目录范围。

## 关机或结束聊天后会发生什么？

当前普通 ChatGPT **不会因为这些脚本在磁盘上，就自动在后台永远运行**。Mac MCP 自己的 Scheduled Tasks 是上游单独的实验功能，需要用户配置/批准，通知也不等于另一个结束的普通 Chat 立刻获得同一个推理会话继续执行的权限。因此本包默认不安排重复后台推理任务，也不承诺“24小时无人值守”。
